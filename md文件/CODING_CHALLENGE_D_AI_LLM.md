# 实习生编程挑战：智能任务管理系统（AI/LLM 方向）

## 概述
构建一个具有智能功能的**任务管理系统**，重点展示你在 AI/ML/LLM 方面的能力。本文档为 **方向 D（AI/LLM 开发方向）** 的专属要求。

**时间限制：** 2-4 小时
**提交方式：** 带有清晰 README 和提交历史的 Git 仓库

---

## 问题描述

创建一个任务管理系统，允许用户借助智能辅助来创建、组织和管理任务。系统应具备后端 API，并实现 AI 驱动的智能功能（如自然语言任务创建、自动标签推荐、语义搜索等）。

---

## 第一部分：核心要求（基础能力）

### 1. 任务 CRUD 操作
实现一个 RESTful API 或服务层，包含以下端点：

- **CREATE** - 新增任务
- **READ** - 通过 ID 获取任务或列出所有任务
- **UPDATE** - 修改任务详情
- **DELETE** - 删除任务

### 2. 任务属性
每个任务应包含：
- `id`（唯一标识符）
- `title`（字符串，必填）
- `description`（字符串，可选）
- `status`（枚举："pending"、"in_progress"、"completed"）
- `priority`（枚举："low"、"medium"、"high"）
- `created_at`（时间戳）
- `updated_at`（时间戳）
- `tags`（字符串数组，可选）
- `due_date`（截止日期，可选，用于自然语言任务创建）

### 3. 数据持久化
选择合适的存储方案：
- **简单**：JSON 文件或 SQLite
- **推荐**：PostgreSQL、MongoDB 等
- **进阶**：数据库 + 缓存层，或数据库 + 向量数据库组合

### 4. 代码质量要求
- 干净、可读且组织良好的代码
- 恰当的错误处理
- 输入校验
- 至少基本的文档（README）
- 清晰的提交信息

## 第二部分：AI/LLM 专项功能

### 1. 智能任务生成

**自然语言创建任务**，例如：
> "明天下午 3 点提醒我买日用品"

系统需要从自然语言中提取结构化信息：
- **标题**（title）：从语句中识别任务主题
- **描述**（description）：补充说明信息
- **截止日期**（due_date）：解析时间表达（明天下午 3 点）
- **优先级**（priority）：根据上下文或关键词推断

**验收标准：**
- 输入一句自然语言，输出结构化的任务对象
- 能处理多种时间表达（今天、明天、下周五、X 小时后等）
- 无法识别时给出合理的默认值或明确提示

### 2. 智能任务组织

- **自动标签推荐**：基于任务内容（标题 + 描述）自动推荐标签，如"购物"、"工作"、"学习"、"健康"等
- **优先级推荐**：使用简单的 ML 模型或 LLM，根据任务内容推断优先级
- **任务分类**：将任务归入预定义或自动生成的类别

**验收标准：**
- 每个任务创建后能自动获得标签和优先级建议
- 用户可覆盖/修改自动推荐结果

### 3. AI 助手功能（至少选择 2 个）

| 功能 | 说明 | 示例 |
|------|------|------|
| **任务拆解** | 将复杂任务拆分为子任务 | "筹备生日聚会" → 订蛋糕、发邀请、买装饰等 |
| **任务摘要** | 生成每日/每周任务摘要 | "本周共有 8 个任务，3 个高优先级待处理" |
| **相似任务检测** | 查找相关/重复任务 | 创建任务时提示"你可能已有类似任务" |
| **智能搜索** | 语义搜索而非关键词匹配 | 搜"买吃的"能命中"采购日用品" |

**验收标准：**
- 至少 2 个功能可实际运行并给出合理结果
- 输出结果结构清晰、易于前端展示

### 4. 实现选项（选择其一）

- **使用大模型 API**：OpenAI API / Anthropic API（需妥善处理 API key，如环境变量）
- **使用本地模型**：HuggingFace、LangChain 等
- **使用嵌入 + 向量数据库**：ChromaDB、FAISS、Pinecone 等
- **构建简单 ML 分类器**：sklearn、PyTorch 等

**推荐组合（按投入产出比排序）：**
1. LLM API（任务生成/拆解/摘要）+ 向量数据库（语义搜索）
2. 本地模型 + 向量数据库（完全离线）
3. 规则/关键词 + sklearn 分类器（无外部依赖，最稳定）

## 常见问题

**问：必须用真实的大模型 API 吗？**
答：不一定。可使用本地模型、规则/关键词 + ML 分类器，或 mock LLM 响应。关键是展示你的 AI 方案设计思路。

**问：如何处理 LLM 返回不稳定 / 超时 / 解析失败？**
答：这是加分点。建议实现重试、降级（失败时回退到规则方案）、输出校验（如用 JSON Schema 约束）。

**问：我可以使用 AI 助手（ChatGPT、Copilot）辅助开发吗？**
答：如果使用了，请在 README 中注明。我们更看重你的理解和决策能力，而非完美的代码。

**问：智能功能应该做成同步还是异步？**
答：视时延而定。LLM 调用通常较慢，建议对耗时操作提供异步或流式响应；简单规则方案可保持同步。
