# 实习生编程挑战：智能任务管理系统

## 概述
构建一个具有智能功能的**任务管理系统**，以展示你在不同专业方向上的编码能力。本挑战旨在评估各个岗位的候选人，包括后端、前端、全栈以及 AI/LLM 开发等职位。

**时间限制：** 2-4 小时
**提交方式：** 带有清晰 README 和提交历史的 Git 仓库

---

## 问题描述

创建一个任务管理系统，允许用户借助智能辅助来创建、组织和管理任务。系统应具备后端 API，并可选择性地包含前端界面和/或 AI 驱动的功能。

---

## 核心要求（所有候选人）

### 1. 任务 CRUD 操作
实现一个 RESTful API 或服务层，包含以下端点：

- **CREATE** - 新增任务
- **READ** - 通过 ID 获取任务或列出所有任务
- **UPDATE** - 修改任务详情
- **DELETE** - 删除任务

### 2. 任务属性
每个任务应包含：
- `id`（唯一标识符）
- `title`（字符串，必填）
- `description`（字符串，可选）
- `status`（枚举："pending"、"in_progress"、"completed"）
- `priority`（枚举："low"、"medium"、"high"）
- `created_at`（时间戳）
- `updated_at`（时间戳）
- `tags`（字符串数组，可选）

### 3. 数据持久化
选择合适的存储方案：
- **简单**：JSON 文件或 SQLite
- **推荐**：MySQL、PostgreSQL、MongoDB 或 Redis
- **进阶**：数据库 + 缓存层组合

### 4. 代码质量要求
- 干净、可读且组织良好的代码
- 恰当的错误处理
- 输入校验
- 至少基本的文档（README）
- 清晰的提交信息

---

## 岗位专项功能（根据你的目标岗位选择）

### 方向 A：后端开发方向

实现以下高级后端功能：

1. **任务筛选与排序**
   - 按状态、优先级、标签筛选
   - 按创建日期、优先级、状态排序
   - 分页支持

2. **任务依赖**
   - 任务可以依赖其他任务
   - 依赖项未完成时，不能将任务标记为已完成
   - 提供查询任务依赖树的 API

3. **性能优化**
   - 为频繁访问的数据实现缓存
   - 数据库查询优化
   - 基本操作的 API 响应时间 < 100ms

4. **系统设计**
   - 扩展到 10 万+ 任务的设计考量
   - 包含一份简短的架构文档

**加分项：**
- 实现搜索功能（全文搜索）
- 添加用户认证/授权
- API 端点限流
- 容器化（Docker）

---

### 方向 B：前端开发方向

构建一个具有以下功能的用户界面：

1. **任务仪表盘**
   - 以组织良好的视图展示所有任务（列表/看板/日历）
   - 优先级和状态的视觉标识
   - 响应式设计（移动端友好）

2. **交互式任务管理**
   - 拖拽以更改状态或重新排序
   - 快捷操作（标记完成、删除、编辑）
   - 实时搜索/筛选

3. **用户体验**
   - 流畅的动画和过渡
   - 加载状态和错误提示
   - 带有有效反馈的表单校验

4. **状态管理**
   - 恰当的状态管理（Context/Redux/Vuex/Pinia）
   - 乐观 UI 更新
   - 优雅处理边界情况

**技术栈选项：**
- React + TypeScript + Tailwind/MUI
- Vue 3 + TypeScript + Element Plus
- 原生 JavaScript（如果你想展示基础功底）

**加分项：**
- 深色模式支持
- 键盘快捷键
- 离线支持（PWA）
- 数据可视化（图表/图形）

---

### 方向 C：全栈开发方向

结合后端和前端要求：

1. **完整应用**
   - 可运行的后端 API（从后端方向功能中选择）
   - 功能完备的前端 UI（从前端方向功能中选择）
   - 前端与后端之间的正确集成

2. **系统架构**
   - 清晰的关注点分离
   - RESTful API 设计或 GraphQL
   - 两层的错误处理

3. **部署考量**
   - Docker compose 配置或部署说明
   - 环境配置管理
   - 基本的 CI/CD 设置（可选，但很加分）

**加分项：**
- 使用 WebSocket 实现实时更新
- 任务附件文件上传
- 导出任务（JSON/CSV/PDF）

---

### 方向 D：AI/LLM 开发方向

使用 AI/ML/LLM 构建智能功能：

1. **智能任务生成**
   - 自然语言创建任务："明天下午 3 点提醒我买日用品"
   - 从自然语言中提取：标题、描述、截止日期、优先级

2. **智能任务组织**
   - 基于任务内容自动推荐标签
   - 使用简单 ML 或 LLM 进行优先级推荐
   - 任务分类

3. **AI 助手功能**（至少选择 2 个）
   - 任务拆解：将复杂任务拆分为子任务
   - 任务摘要：生成每日/每周任务摘要
   - 相似任务检测：查找相关任务
   - 智能搜索：语义搜索而非关键词匹配

4. **实现选项**
   - 使用 OpenAI API / Anthropic API（提供 API key 处理方式）
   - 使用本地模型（HuggingFace、LangChain）
   - 使用嵌入 + 向量数据库（ChromaDB、FAISS）
   - 构建简单的 ML 分类器（sklearn、PyTorch）

**加分项：**
- 为任务知识库实现 RAG
- 多智能体系统（规划智能体 + 执行智能体）
- 针对任务领域微调的模型
- 提示词优化与测试

## 常见问题

**问：我可以使用外部库/框架吗？**
答：可以，但请说明你的选择理由。使用过多不必要的库可能会对你不利。

**问：我可以使用 AI 助手（ChatGPT、Copilot）吗？**
答：如果使用了，请在 README 中注明。相较于完美的代码，我们更看重你的理解和决策能力。

**问：如果我无法完成所有内容怎么办？**
答：提交你已有的成果，并清晰说明哪些已完成、哪些待完成。质量 > 数量。

**问：我可以选择多个方向吗？**
答：进阶候选人可以组合方向（例如：全栈 + AI 功能），但要确保质量不受影响。

**问：我应该部署应用吗？**
答：不强制，但提供一个在线演示会很加分。至少提供清晰的本地安装说明。
